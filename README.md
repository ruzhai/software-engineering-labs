# 软件工程实验二 · 小型酒店预订管理系统 设计与建模

把实验一的 36 条需求转成可以照着写代码的设计：UML 结构与交互模型、十个模块的划分与依赖、十二张表的数据库结构、16 屏界面。

## 目录

| 路径 | 内容 |
|---|---|
| `实验报告/report.pdf` | 定稿报告，64 页 |
| `实验报告/*.tex` | 报告源码，`report.tex` 为主文件，`ch1`–`ch8`、`app` 各章 |
| `UML/` | 16 张图，每张 `.puml` 源文件配同名 `.png` |
| `UI界面/` | 16 屏界面，按 2 倍像素导出 |
| `design.md` | 模块划分与接口约定的文字版 |
| `2.md` | 课程下发的作业要求 |
| `_过程材料/` | 绘图与排版的中间产物（不入库）；其中三份记录随仓库保留 |

## 重新生成

报告：

```bash
cd 实验报告 && xelatex report.tex && xelatex report.tex
```

两遍是必须的，目录与交叉引用在第二遍才稳定。

UML：

```bash
java -jar plantuml.jar -charset UTF-8 -tpng UML/*.puml
```

## 关于提交历史

本仓库从定稿建立，此前的设计迭代没有以提交记录的形式保留下来。

这不是省略，是不想把它编成提交：这里的每一个文件都是多轮讨论后的结果，把它拆成「AI 初稿 / 人工修改」两个提交，那个「初稿」是我重写出来的，不是它当时真实的样子——那样得到的修改记录看着完整，实际是假的。

真实的迭代过程记在文字里：

- 报告第 7 章逐次记录了五次使用大模型的过程，每次写清使用场景、生成了什么、发现了什么错、最后改成了什么；
- `_过程材料/AI使用记录.md` 是同一批过程的原始版本，保留了讨论中的判断依据；
- `_过程材料/UI重做对照表.md` 记录了 16 屏重画时的功能清单，`UI设计规格书.md` 是重画前的规格约束。
