# 迭代记录

这份文件补记两类在报告里没有展开的过程：一是排版与出图阶段踩到的具体问题，二是最后核对时发现的不一致。设计决策本身的迭代写在报告第 7 章，这里不重复。

记录口径与报告第 7 章一致：只写真实发生过的事。这份记录里没有日期——每个问题都是在同几轮编译里出现的，精确到天的归属记不准，就不写。

---

## 一、图表排版

### 1. 表格被压出页底

第 5 章的四张时序图是浮动体，会漂到第 6 章开头，把第 6 章的表 19、表 20 挤出版心——表 19 的最后一行被截断，`bottomrule` 直接丢失。

三次尝试，前两次都失败了：

| 尝试 | 结果 |
|---|---|
| `\needspace{8cm}` / `{9cm}` | 完全无效，溢出原样复现 |
| `\FloatBarrier`（placeins）放在章末 | 溢出消失，但页数 59→60，第 31–33 页变成每页一张图、约 45% 空白的纯浮动页 |
| 表 19、20 改成 `xltabular` 可跨页表 | 彻底解决 |

`\needspace` 失效的原因是它量的是 `\pagetotal`，而浮动体要到 `\output` 阶段才插入页面，量的时候看不见它们。`\FloatBarrier` 失效的原因是屏障摆在章末、正文已经排完，四张约 16cm 高的图只能被逐页单放。

`xltabular` 是唯一对症的做法：表本身可以拆到下一页，并且能配 `\endfirsthead` / `\endhead` / `\endfoot` / `\endlastfoot` 给出续页表头和「续下页」标记。

### 2. 图与说明文字脱节

四张时序图被推到一起，正文说明留在上一页。在 `\subsection{交互图}` 前加 `\clearpage` 会把当时仍在队列里的前一张图（活动图：支付回调）单独冲成第 30 页，约 55% 空白。

把 `\clearpage` 前移到那张活动图之前才解决：清空了队列，又不牺牲任何一张图。

### 3. 段末孤行

第 32 页顶部只剩「过一天。」三个字。加 `\widowpenalty=10000` / `\clubpenalty=10000`，让段首段尾各至少保住两行。

### 4. 附录 B 的文件名从中间折断

原来用 `quote` 环境 + `\\` + 手工 `\hspace` 对齐，长文件名（如「UML活动图_支付回调与订单生效.png」）会被折成两行，第二行只剩「效.puml」。

改成 `\raggedright` + 每行一个 `\par` + `\qquad` 分隔，并只列 `.png`（`.puml` 用一句文字说明数量），不再依赖手工对齐。

### 5. 附录 B 标题落在页底

`\section{提交物清单}` 前只有两行正文就被断页，标题孤零零挂在页底。加 `\needspace{9cm}` 解决——这一次 `\needspace` 是有效的，因为它量的正文块里没有浮动体。

### 6. 附录 A 的「REQ-001」被折行

表 25 的「需求」列设为 1.45cm 时，`REQ-001` 这样的拉丁串被折成「REQ-」和「001」两行，36 行全部如此。「需求」列加宽到 1.75cm 后消失。

中间还有一次反复：为了给别的列腾地方，把「模块」列从 2.7cm 收到 2.35cm，结果 `M2/M3/M4/M7` 溢出 8.68pt——拉丁串不会在 `/` 处断行，收窄列宽反而制造了新问题，最后又退回 2.65cm。

## 二、最后核对时发现的不一致

两处都是「文中写的」和「实际存在的」对不上，靠肉眼翻页很难发现，用脚本差集才逼出来：

1. **附录 B 清单与实际文件名不符**。清单里写 `10_checkout.png`，实际文件名是 `10_housekeeping.png`。做法是把附录 B 里列出的文件名和 `UI界面/`、`UML/` 的真实目录各取一份排序集合，做双向差集，四个方向都为空才算过。

2. **附录 A 引用了不存在的表号**。原文写「图号按第 5 章的表 5.1 编号」，但报告的表是全局流水编号，根本没有「表 5.1」。改为 `\ref{tab:uml_list}`，并给第 5 章的 UML 图清单补了 label。

第二处是第 7 章 U-05 里记过的同一个毛病：手写相对编号，扩写后就会失效。这次它又发生了一次，只不过发生在自己写的附录上。

## 三、出图

- UML：16 张全部由 PlantUML 生成，统一 `skinparam`（白底、深灰线、单一强调色、Microsoft YaHei），`.puml` 与 `.png` 同名放在 `UML/`。
- UI：16 屏用 HTML + CSS 写成，共享一套设计令牌，按 2 倍像素密度导出（顾客端 780×1688，后台 2880×1800）。中途放弃过 Pixso 方案——它一次吃不下 16 屏，而且会漏字段、编数字，改回代码生成之后才能用脚本批量重导。
